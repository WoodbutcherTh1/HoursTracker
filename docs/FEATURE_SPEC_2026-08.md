## 0. سياق عام

- المشروع: iOS app لتتبع ساعات العمل + قانون العمل الإسرائيلي (125%/150%).
- نظام الثيم الحالي: `HoursTracker/Utilities/HomeAccentTheme.swift` — `ObservableObject` واحد
  (`HomeAccentTheme.shared`) بيخزن لون accent بصيغة hex بـ `UserDefaults`، مع مصفوفة
  presets مسماة. أي نظام تخصيص جديد (لون خلفية، رؤية الأيقونة العائمة...) لازم يتبع نفس
  النمط (Published property + UserDefaults + presets array) للحفاظ على الاتساق.
- نظام LLM الحالي: `HoursTracker/Managers/Scanner/` فيه نمط Router جاهز
  (`PayslipLLMRouter`, `ScannerLLMRouter`) بترتيب: Gemini (لو فيه مفتاح) → OpenAI-compatible
  (لو فيه مفتاح) → Local heuristic (دايمًا كخط أخير بدون AI حقيقي). المفاتيح مخزّنة بـ
  `KeychainStore` (`.geminiAPIKey`, `.secondaryAPIKey`). **هاد النمط (BYOK) هو الأساس
  لمساعد الـ AI الجديد كمان — راجع بند 3.**
- `ExportManager.swift` / `FullDataExportManager.swift`: منطق توليد PDF/TXT/Word/Markdown
  موجود وجاهز — يُعاد استخدامه لتوليد ملفات المساعد، مش نكتب منطق تصدير جديد.
- `OvertimeCalculator` + `DayPayBreakdown`: مصدر الحقيقة الوحيد لحساب الساعات
  العادية/125%/150%/الأجر. أي رقم بيطلع للمستخدم (من المساعد أو غيره) لازم يمر من هون،
  مش يُحسب يدويًا بمكان تاني.

## 1. شاشة الهوم: حالة "بعد الدخول"

**الملفات:** `HoursTracker/Views/HomeView.swift`, `HoursTracker/Views/HomeVitalityViews.swift`

- لما يعمل المستخدم Clock In: عنصر "الباب" (زر الدخول/الخروج) يتحول للون التحذيري
  الثابت (coral) المستخدم أصلاً لحالة "active session" — **لا تربطه بـ `HomeAccentTheme`**،
  هو لون دلالي ثابت بتصميم مقصود (راجع التعليق أعلى `HomeAccentTheme`).
- المربعات الثلاثة (Today hours / Week hours / Month shift count — موجودة أصلاً كـ
  `todayHours`, `weekHours`, `monthShiftCount` بـ `HomeView.swift`) تبقى ظاهرة بعد الدخول
  كمان، بس بحجم أصغر وستايل بصري مختلف عن حالة "قبل الدخول" (مثلاً: أفقية مضغوطة بدل
  بطاقات كبيرة، أو شفافية أقل تركيزًا بصريًا لأنها معلومات ثانوية أثناء العد الحي).
- أضف Picker Gross/Net (زي `PayDisplayMode` بـ `HistoryView.swift`) بجانب العد الحي
  للساعات/النقود، يستخدم نفس `OvertimeCalculator` — لا منطق حساب جديد.

## 2. History: عداد أيام العمل

**الملفات:** `HoursTracker/Views/HistoryView.swift` (`stickySummaryBar`), وأي مكان فيه
"Summary shifts".

### التعريف الدقيق (نقطة حسمناها أثناء المراجعة)

⚠️ **لا تستخدم منطق `monthShiftCount` الموجود بـ `HomeView.swift` كما هو** — هو بيعد
عدد الجلسات المكتملة (`completedSessions.filter{...}.count`)، مش عدد الأيام المميزة. لو
المستخدم دخل/طلع مرتين بنفس اليوم، `monthShiftCount` الحالي بيطلع 2 مش 1.

**العداد الجديد لازم يعد أيام تقويمية مميزة (distinct calendar days)** فيها جلسة واحدة
مكتملة على الأقل هالشهر التقويمي الحالي (`calendar.isDate(_:equalTo:toGranularity:.month)`،
نفس المرجعية المستخدمة بـ `monthShiftCount` الحالي، بس مع `Set<DateComponents>` أو مقارنة
`startOfDay` لإزالة التكرار قبل العد).

### السلوك المطلوب

- بجانب رقم عدد الأيام (بـ `stickySummaryBar` أو مكان مشابه بـ History): لما المستخدم
  يكون بحالة Clock In حاليًا **ولليوم الحالي مش محسوب أصلاً هالشهر بعد** (يعني هاد اليوم
  رح يكون أول جلسة مكتملة فيه)، اعرض بابل "+1?" بالأخضر مع أنيميشن قفزة (bounce/pop-in).
- الـ "+1?" يختفي أوتوماتيكيًا لحظة Clock Out، وبنفس اللحظة الرقم الأساسي (عدد الأيام)
  يزيد بـ 1 فعليًا — إذا وبس إذا هاد اليوم مش كان محسوب من قبل هالشهر.
- إذا المستخدم أصلاً اشتغل اليوم (جلسة مكتملة سابقة نفس اليوم) وعمل Clock In تاني: **ما
  تظهر "+1?"** لأنه اليوم أصلاً محسوب.
- كرر نفس الرقم + نفس أنيميشن القفزة الخضراء بقسم "Summary shifts" (أو مكافئه) — نفس
  مصدر البيانات، عرض مكرر بس.

## 3. مساعد AI عائم (البند الأكبر)

### 3.1 القرارات المعمارية (محسومة، لا تُناقش من جديد)

| القرار | الاختيار |
|---|---|
| تمويل استدعاءات الـ API | **BYOK** — نفس نمط `KeychainStore` الحالي (Gemini/OpenAI key). لا تكلفة على المطوّر. لو ما في مفتاح محفوظ، المساعد يعرض حالة "غير مفعّل — أضف مفتاح API بالإعدادات" بدل ما "يشتغل مجانًا". |
| بنية الفهم/التوجيه | **نظام أدوات مرن (tool-calling)** — ممنوع ليستة ثابتة من 100-200 طلب محدد مسبقًا. |
| نطاق النص القابل للتخصيص (بند 6) | Home wordmark بس |
| خلفية داكنة (بند 7) | خلفية عامة بكل الشاشات، مش شريط التابات بس |

### 3.2 المعمارية التقنية المقترحة

**لا تبني LLM يحسب الأرقام بنفسه.** البنية:

1. **مصنّف/موجّه (router LLM أو حتى tool-calling مباشر بموديل واحد)**: ياخد سؤال
   المستخدم بالعربي/العبري/الإنجليزي، وقراره الوحيد هو: أي دالة بيانات (tool) يشغّل، بأي
   بارامترات. مجموعة الـ tools تكون أدوات بيانات **قابلة للتركيب**، أمثلة:
   - `filterSessionsByDateRange(start, end)`
   - `filterSessionsByClockInAfter(time: "17:00")`
   - `filterSessionsByOvertimeTier(tier: .ot125 | .ot150 | .regular)`
   - `findDaysWithoutSessions(month)` (لطلب "الليالي يلي ما اشتغلت فيهن")
   - `aggregatePay(sessions, mode: .gross | .net)`
   - `generateDocument(sessions, format: .pdf | .word | .markdown | .txt, groupBy: ...)`
   كل الـ tools هاي دوال Swift عادية بتشتغل على `viewModel.sessions` الحقيقية — **صفر
   استدعاء LLM لحساب رقم**. الـ LLM بس بيقرر *أي* دالة وبأي فلاتر، والنتيجة النهائية
   (الملف) تتولد عبر `ExportManager` الموجود.
2. **لو السؤال برة النطاق** (مافي tool مناسب له إطلاقًا — طقس، أخبار، دردشة عامة): رجّع
   رسالة رفض ثابتة من الكود (مش من الـ LLM بحرية) — هيك الحصر بمواضيع التطبيق مضمون
   هيكليًا مش بس بروبمت قابل للالتفاف عليه.
3. **منع الهلوسة**: كل رقم بيوصل للمستخدم لازم يكون خارج من `OvertimeCalculator` أو
   فلترة مباشرة على `viewModel.sessions`/`viewModel.settings` — ممنوع الـ LLM "يخترع"
   رقم أو تاريخ مش موجود فعليًا ببيانات المستخدم.

### 3.3 الأيقونة العائمة

- ظاهرة فوق كل الـ Tabs (Home/History/Export/Settings)، جهة يمين أو يسار (افتراضي:
  اليسار — أبعد عن إبهام اليد اليمنى المستخدمة عادة بالتنقل بالـ tab bar باللغات RTL،
  لكن هاي نقطة ذوقية، عدّلها لو حسيت العكس أفضل).
- Draggable: المستخدم يقدر يسحبها لجهة تانية، والموضع يتخزن بـ `UserDefaults`.
- Long-press 3 ثواني: تظهر X صغيرة جنبها، الضغط عليها بيخفيها.
- تفعيل/تعطيل + تغيير لون/ستايل الأيقونة: من نفس شاشة تخصيص الألوان (راجع
  `HomeThemePickerSheet.swift` كمرجع بصري وبنيوي)، بنفس نمط `HomeAccentTheme`
  (`ObservableObject` جديد أو توسعة الموجود، مع `Published var isVisible`,
  `Published var position`, `Published var iconStyle`).
- الستايل البصري: مستوحى من نفس هوية التطبيق (استخدم `HomeAccentTheme.shared.accent`
  كلون افتراضي للأيقونة، مو لون AI عام بعيد عن هوية التطبيق).

### 3.4 سلوك الضغط على الأيقونة

الضغطة العادية (مش الـ long-press الخاص بالإخفاء، راجع 3.3) بتفتح **شباك تشات صغير**
(sheet/popover فوق الشاشة الحالية، مش تنقل لصفحة كاملة) بواجهة مصممة بعناية — مو حقل نص
عادي. المطلوب إحساس "منتج مصقول" (polished product)، مو إضافة تقنية سريعة:
- حالة فارغة (أول فتح) بترحيب وأمثلة جاهزة قابلة للضغط (suggestion chips) توضح للمستخدم
  شو نوع الأسئلة المسموحة ("الساعات الإضافية هالشهر؟"، "الأيام يلي ما اشتغلت فيهن؟"...) —
  هاي كمان بتقلل احتمال إنه يسأل سؤال برة النطاق من الأساس.
- فقاعات محادثة (chat bubbles) بهوية بصرية متسقة مع `HomeAccentTheme.shared.accent`
  ونفس لغة التصميم بباقي التطبيق (مو UI ذكاء اصطناعي جنيريك مستعار من مكان تاني).
- لما المساعد يرجع ملف (PDF/Word/...): يظهر كبطاقة معاينة داخل المحادثة نفسها مع زر
  حفظ/مشاركة مباشر (نفس Share Sheet المستخدم بـ `ExportView`)، مش مجرد رابط نصي.
- Loading state واضح أثناء انتظار رد الـ LLM (المساعد بيعتمد على شبكة فعليًا — راجع 3.1).

## 4. تصحيح اسم العلامة التجارية (باغ حقيقي موجود)

**الملف:** `HoursTracker/Views/HomeVitalityViews.swift`, حوالي السطر 492-504
(`HomeBrandTitle`)

الكود الحالي:
```swift
HStack(spacing: 0) {
    Text("Hour").foregroundStyle(.white)
    Text("Trackers").foregroundStyle(accent)
}
```
هاد بيطلع "HourTrackers" (كلمتين غلط: "Hour" بدل "Hours"، و"Trackers" بدل "Tracker").
بالإضافة: بما إنه التطبيق RTL-aware (عربي/عبري)، الـ `HStack` ينعكس بصريًا بلغات RTL
ويطلع "TrackersHour" بالضبط زي ما لاحظ المستخدم بالسكرين شوت.

**المطلوب:**
1. صحح الكلمتين: `"Hours"` (أبيض) + `"Tracker"` (نيون) = "HoursTracker" الصحيح.
2. ثبّت اتجاه العرض LTR على هاد الـ `HStack` تحديدًا (`.environment(\.layoutDirection, .leftToRight)`
   أو ما يعادلها) عشان الاسم ما ينعكس بلغات RTL — علامة الاسم/الـ wordmark ما يجب تتأثر
   باتجاه لغة الواجهة.
3. أضف حقل نصي بشاشة تخصيص الألوان (نطاق: Home wordmark بس، قرار محسوم) يسمح للمستخدم
   يكتب نص بديل (اسمه الشخصي مثلاً) بدل "HoursTracker" — تخزين بـ `UserDefaults` بنفس
   نمط `HomeAccentTheme`. لون النص البديل: يتبع نفس منتقي اللون الموجود (accent).

⚠️ **محدودية لازم توضح للمستخدم إذا سأل:** هاد التخصيص ما بيغيّر اسم أيقونة التطبيق تحت
الشاشة الرئيسية لجهاز iOS (`CFBundleDisplayName`) — هاد ثابت وقت البناء، iOS ما بسمح
بتغييره ديناميكيًا من جوا التطبيق.

## 5. تخصيص لون الخلفية الداكنة (عام، مش بس التاب بار)

**القرار المحسوم:** الخلفية العامة الداكنة بكل الشاشات (Home, History, Export,
Settings...)، مش شريط الـ tab bar بس.

- ابحث/عرّف نظام لوني موحّد (Design token واحد، مثلاً `AppBackground.current` بنمط
  `HomeAccentTheme` نفسه: `ObservableObject` + `UserDefaults` + hex + presets)، واستبدل
  كل استخدام مباشر للون الخلفية الداكن الثابت بهاد الـ token بدل ما يكون كل View عم يحدد
  لونه الخاص.
- Presets مقترحة (أسماء واضحة للمستخدم العادي، مش أسماء غامضة):
  - `Midnight` (الافتراضي الحالي تقريبًا، أغمق درجة)
  - `Charcoal`
  - `Slate`
  - `Graphite`
  - `Onyx`
  (بدل الأسماء يلي اقترحها المستخدم زي Crow/Raven/Oil — هاي أسماء إبداعية بس أقل وضوحًا
  للمستخدم العادي وقت الاختيار. لو المستخدم يصر عليها بعد ما يشوف المعاينة، خليها.)
- لازم معاينة حية (live preview) بشاشة الاختيار قبل التأكيد، بنفس تجربة
  `HomeThemePickerSheet.swift` الحالية للألوان.
